# Организация и счёт — Orchestrator

SDK `@zapas/api/orchestrator` → проверка ответа/mapper → доменные Company/Account →
TanStack Query → страницы. Auth profile не содержит компаний, реквизитов или ролей.
Browser transport/CSRF/refresh общий с Auth/Profile, второго входа нет.

Реализованы server pagination, выбор организации и отдельного RUB-счёта,
создание, редактирование, архивирование и ручной остаток; WRITE по роли OWNER/ACCOUNTANT,
архив/VIEWER/unknown role только для просмотра. Роль и permissions приходят из
Orchestrator; backend проверяет доступ заново. Номер/ИНН/КПП остаются строками.
Отсутствующий остаток не заменяется нулём; большие и отрицательные суммы выводятся
через точный Amount без NumberFlow. Клиент не суммирует счета и не вычисляет баланс.

URL хранит только выбранные UUID. Смена компании сбрасывает account; Query keys
содержат company/account/page, незавершённые запросы отменяются. Mapper не принимает
счёт другой компании. 403/404 не показывают прежний приватный ресурс; outage
оставляет доступные сохранённые данные. Приватные запросы выключаются при logout.

POST получает UUID один раз на явную попытку. CommandAttempt копирует исходные
данные в памяти; потеря ответа/5xx/неопределённый refresh сохраняют payload и key.
Повтор после последующего 429/403 также не меняет прежнюю попытку. Автоматического
retry нет; при неопределённом исходе поля заблокированы и доступна явная отправка
прежнего запроса. Уход к списку отдельно подтверждается, список перечитывается.
Деньги/контакты/токены не пишутся в localStorage, ошибки содержат статические тексты.

PUT отправляет все реквизиты с явными nullable fields и quoted If-Match.
Конфликт/неопределённый результат сохраняет черновик; отдельный Query читает
актуальный ресурс. Явный выбор обновляет только известную серверную версию или
загружает реквизиты; повторная запись требует отдельного Save. Версия не вычисляется.
Архивирование доступно OWNER с подтверждением, прежним key/version для replay.
Ручной остаток — отдельный объект, не правка выписки. Он принимает точные signed
строки NUMERIC(19,2), календарную дату и основание. Account после сохранения читается
заново: старый anchor не обязан быть последним остатком. Будущая дата запрещена,
нулевой/отрицательный допустимы. MoneyInput — поставленный F2 #17.
